# Olvii

Локальная голосовая связь для дома. MVP: два Android-устройства, обычный вызов с явным ответом, отклонение, завершение и отключение микрофона.

## Архитектура

- Весь сервер — ASP.NET Core / .NET 10, без Asterisk, внешней базы или облака.
- Сервер управляет доступностью устройств и состоянием звонка через WebSocket API.
- Kotlin-клиент использует готовую нативную WebRTC-библиотеку: Opus, подавление эха, шифрование медиапотока и согласование соединения.
- Звук идёт непосредственно между устройствами. Сервер не принимает и не записывает звук. Внешние STUN/TURN-сервисы не используются.
- Серверный медиадвижок для этого сценария не требуется. Для будущего SIP-домофона можно рассмотреть .NET-библиотеку [SIPSorcery](https://github.com/sipsorcery-org/sipsorcery), отдельно проверив совместимость оборудования и условия лицензии выбранной версии.

## Запуск сервера

Нужен .NET SDK 10. В PowerShell из корня репозитория:

```powershell
$env:Olvii__AccessKey = 'replace-with-your-own-long-random-key'
dotnet run --project src/Olvii.Server -- --urls http://0.0.0.0:5080
```

Используйте собственный непустой общий ключ. Сервер без него не запускается. Для локальной проверки допустим короткий ключ, например `123`. Разрешите входящие TCP-соединения на порт 5080 только из домашней сети. Не публикуйте этот порт в интернете.

HTTP/ws в MVP предназначены для тестирования в доверенной LAN: общий ключ и сигнализация передаются без TLS; WebRTC-аудио шифруется отдельно. Для постоянного использования настройте HTTPS на Kestrel с сертификатом, которому доверяют устройства, и используйте адрес `https://...` в приложении. Отключение проверки сертификата не предусмотрено.

## Android

Откройте каталог `android` в Android Studio. Нужны JDK 17 или новее, Android SDK 36 и Gradle 9.1.0. Минимальная версия устройства — Android 8 (API 26).

```powershell
cd android
.\gradlew.bat assembleDebug
```

APK: `android/app/build/outputs/apk/debug/app-debug.apk`.

1. Установите APK на два устройства в одной локальной сети. Изоляция Wi-Fi-клиентов должна быть выключена; между устройствами должен проходить UDP.
2. На обоих устройствах разрешите доступ к микрофону.
3. Введите адрес сервера, например `http://192.168.1.10:5080`, разные отображаемые имена и одинаковый ключ сервера.
4. Нажмите «Подключиться» на обоих устройствах. В списке появится второе устройство.
5. Нажмите «Позвонить». На втором устройстве прозвучит звонок; нажмите «Ответить».
6. Проверьте звук в обе стороны, отключение микрофона и завершение с любой стороны. Для проверки эха разнесите устройства по разным комнатам.

Микрофон и WebRTC-соединение создаются только после принятия вызова. Экран остаётся включённым. При уходе приложения в фон подключение и звонок завершаются намеренно: фоновая телефония в эту версию не входит. После возвращения нажмите «Подключиться». Ключ не сохраняется на диск; адрес, имя и случайный идентификатор устройства сохраняются.

## Веб-клиент

Сервер отдаёт минимальную страницу с инлайн-скриптом по `/`. Для проверки с одним телефоном:

1. Запустите сервер на компьютере и откройте на нём `http://localhost:5080`.
2. Введите имя браузерного устройства и тот же ключ, что в Android-приложении, нажмите «Подключиться».
3. На телефоне подключитесь к LAN-адресу компьютера, например `http://192.168.1.10:5080`.
4. Позвоните из браузера или с телефона; на принимающей стороне нажмите «Ответить».
5. Разрешите браузеру микрофон. Если автозапуск звука заблокирован, нажмите ▶ на аудиоплеере.

Микрофон браузера доступен только в безопасном контексте: `http://localhost` на компьютере с сервером либо HTTPS с доверенным сертификатом. Обычный `http://192.168…` для веб-клиента не подходит. Страницу нужно открывать через сервер, не как локальный HTML-файл. Используйте наушники, если устройства находятся рядом. Входящий вызов отображается на странице и в заголовке вкладки; звукового рингтона в веб-клиенте нет.

Можно открыть две вкладки для проверки протокола: каждая получает отдельный случайный идентификатор. Ключ хранится только в поле текущей страницы, не сохраняется в браузерное хранилище. Закрытие страницы освобождает микрофон и завершает звонок.

## API v0

`GET /health` — проверка работы сервера, без авторизации.

`GET /api/devices` — доступные устройства: `id`, `name`, `busy`.

`WS /api/connect?id=<UUID>&name=<name>` — регистрация устройства и канал команд/событий. Для обоих `/api` endpoints нужен HTTP-заголовок `Authorization: Bearer <ключ>`.

Для браузера: `POST /api/tickets` с тем же заголовком возвращает `{ticket}` (одноразовый билет на 30 секунд). Затем `WS /api/connect?id=<UUID>&name=<name>&ticket=<ticket>` с Origin того же сервера. Общий ключ не помещается в URL. Android продолжает использовать заголовок Authorization без изменений.

Команды JSON:

| type | Остальные поля | Назначение |
|---|---|---|
| `call` | `target` | Позвонить устройству |
| `accept` / `reject` | `callId` | Принять / отклонить входящий вызов |
| `hangup` | `callId` | Отменить или завершить свой вызов |
| `offer` / `answer` | `callId`, `sdp` | Обмен SDP после принятия вызова |
| `ice` | `callId`, `candidate: {sdpMid, sdpMLineIndex, candidate}` | Обмен ICE-кандидатами |

События: `welcome`, `devices`, `ringing`, `incoming`, `accepted`, `offer`, `answer`, `ice`, `ended`, `error`. Событие `accepted` содержит `initiator`: только инициатор создаёт offer. `incoming` содержит имя вызывающего устройства. `ended` содержит причину: `rejected`, `hangup`, `timeout`, `disconnected`.

Один звонок на устройство. Ответить может только получатель. Первый ответ фиксируется сервером. Через 30 секунд без ответа вызов завершается; на SDP-согласование после принятия также отводится 30 секунд. Отключение сигнализации завершает вызов. Повторный вход с тем же UUID отклоняется. Общий ключ — простая модель доверия для домашнего прототипа, не индивидуальная авторизация устройств.

## Проверки

```powershell
dotnet build src/Olvii.Server
# При запущенном сервере, с тем же Olvii__AccessKey:
dotnet run --project tests/Olvii.Smoke -- http://localhost:5080
```

Smoke-тест использует настоящие WebSocket-соединения: проверяет авторизацию, запрет SDP до ответа, занятость, запрет управления чужим вызовом, отклонение, принятие, SDP/ICE, завершение и отключение клиента. Он не проверяет передачу звука: для этого нужен описанный выше тест на двух устройствах.

Он также проверяет выдачу браузерной страницы, авторизацию билетов, запрет повторного использования билета и чужого Origin.

Для автоматической проверки веб-клиента при запущенном сервере (Node.js 22+, браузер на Chromium, тот же `Olvii__AccessKey`):

```powershell
node tests/browser-smoke.mjs 'C:\путь\к\браузеру.exe' http://localhost:5080
```

Тест запускает отдельный headless-браузер с временным профилем и искусственным аудио, проверяет принятие/отклонение, получение аудиопакетов в обе стороны, mute и освобождение микрофона. Настоящий микрофон не используется. Совместимость звука с Android и слышимость проверяются вручную.

## Границы MVP

Нет фонового приёма, push, видео, домофона, групповых звонков, истории и автоматического переподключения. Настройки звонков хранятся в памяти; перезапуск сервера завершает звонки. Для следующего этапа: проверка аудио на реальных устройствах, затем Android Core-Telecom/фоновая работа и индивидуальное сопряжение устройств.
